# Defence Before Fix conformance

Status: **partial at both levels**. go-qa-ci does not claim conformance. The machine-readable
declaration is [`defence-before-fix.toml`](../defence-before-fix.toml); this page is the evidence
record and `internal/declaration` with `tests/conformance` fail the build when the two disagree: a
clause marked Gap or Partial here must have a gap in the declaration, and a declared gap must be
marked Gap or Partial here.

Specs: method 1.1.0, detector 1.0.0, toolchain 0.2.0 (https://defence-before-fix.github.io/),
graded as TOOLING-SPEC 9.1 requires: the two levels separately, neither implying the other.

A status is **Met** (the evidence column names how it is proved), **Partial** (some of the clause
holds; the gap is recorded), **Gap** (the clause fails) or **N/A**. A non-empty gap record is a
statement of where the project stands, not a claim (TOOLING-SPEC 9.2).

## Recorded gaps

Every gap above is recorded once, in `defence-before-fix.toml`, with the file that holds the full
account. Further known limits that are not a failure of a named clause, kept here so they are not
mistaken for conformance:

- The pinned external tools are installed from `tools.lock` by `scripts/install-tools.sh`; release
  archives are pinned for linux/amd64 only.
- `govulncheck` needs the network to fetch the vulnerability database, so `vuln` cannot run offline.
- The `licences` runner of the design brief is not built.
- TOOLING-SPEC 9.1 grades the project level against the toolchain spec and also against section 7
  of the method spec (conforming defences, remediation documents, discoverable decisions). The
  project-level table above grades TOOLING-SPEC sections 4 to 7 only; the method-spec section 7
  basis is not graded here, and most artefact-level rows say "as the project level", so a reader
  finds less evidence there than a separate grade would give.
- `actionlint` is pinned inline in the CI workflow, not in `tools.lock`, and `shellcheck` is the
  runner image's, so `tools.lock` does not pin every external tool CI uses.
- Tests that are missing, not failing: nothing exercises `.github/scripts/write-denylist.sh` (its
  missing-secret failure and fork-PR warning are read, not tested); the download, checksum and
  extract paths of `scripts/install-tools.sh` run only in the CI jobs that install the tools, not in
  `go test`; the script's version probe for `[go]` tools reads the `mod` line of `go version -m`,
  which is the main module's version and so would misreport a tool whose command lives in a
  submodule of its pin.
- `internal/declaration` reconciles which clauses are Gap or Partial against the declared gaps one
  to one, but does not compare a gap's summary with the evidence text here, so the two descriptions
  can drift apart without a test failing.
- The `Public safety` workflow fails on every push until the owner sets the `GQACI_DENYLIST`
  repository secret (docs/PUBLICATION-CHECKLIST.md): it is designed to fail loudly without it, and
  until then the denylist scan has never run in CI.
- No conformance verdict from an independent grader exists; this page is the project's own
  reading of the specifications and is not a verdict.
